Rigor de Engenharia

Modelagem do Algoritmo de Precificação (RF 12)

Exemplo de lógica estruturada em Portugol que protege a margem de lucro impedindo o cadastro de preços sem custo prévio ou abaixo do custo total (RN-01 e RN-02).

// RF 12 - Cálculo do Preço Sugerido via Markup e Proteção de Custo
Início
    custo_aquisicao <- obter_custo_entrada(codigo_produto)
    // Validação RN-01: Bloquear sem custo cadastrado
    Se custo_aquisicao == 0 OU custo_aquisicao == nulo então
        exibir_alerta("Custo de entrada obrigatório para calcular preço")
        bloquear_cadastro_preco()
        Retornar
    FimSe
    custo_total <- custo_aquisicao * (1 + impostos/100) * (1 + despesas/100)
    markup <- 100 / (100 - margem_lucro_desejada)
    preco_sugerido <- custo_total * markup
    // Validação RN-02: Bloquear venda abaixo do custo de aquisição
    Se preco_definido < custo_total então
        exibir_alerta("Preço abaixo do custo total. Aprovação obrigatória.")
        Ler aprovacao_gerencial
        Se aprovacao_gerencial == falso então cancelar_cadastro_preco()
    FimSe
Fim

RN-01: Rastreabilidade Obrigatória

O software barra a digitação de preços de venda se o produto não tiver custo de lote ativo na nota de entrada.

RN-02: Trava de Prejuízo Preventivo

O sistema bloqueia vendas com margens negativas. Qualquer exceção de preço promocional exige token/credencial de gerência.

Modelagem do Dashboard Gerencial (RF 15)

Algoritmo estruturado para consolidação automática de faturamento, ticket médio e lucratividade em tempo real para os painéis de gestão.

// RF 15 - Consolidação de Métricas do Dashboard Gerencial
Início
    periodo_selecionado <- obter_periodo_filtro()
    vendas_periodo <- buscar_vendas_db(periodo_selecionado)
    faturamento_total <- 0
    lucro_bruto <- 0
    ticket_medio <- 0
    Para cada venda em vendas_periodo faça
        faturamento_total <- faturamento_total + venda.valor_total
        lucro_bruto <- lucro_bruto + (venda.valor_total - venda.custo_total)
    FimPara
    Se total_vendas(vendas_periodo) > 0 então
        ticket_medio <- faturamento_total / total_vendas(vendas_periodo)
    FimSe
    atualizar_painel_visual(faturamento_total, ticket_medio, lucro_bruto)
Fim

Modelagem do Estoque Mínimo e Alertas (RF 03)

Pseudocódigo estruturado para monitoramento constante dos saldos físicos e disparo de alertas preventivos contra rupturas de estoque.

// RF 03 - Monitoramento Contínuo e Alertas Críticos
Início
    Para cada produto em catalogo_produtos faça
        estoque_atual <- obter_saldo_fisico(produto.codigo)
        estoque_minimo <- produto.limite_seguranca
        Se estoque_atual <= estoque_minimo então
            Se estoque_atual == 0 então
                registrar_alerta(produto.codigo, "RUPTURA CRÍTICA")
                bloquear_venda_pdv(produto.codigo)
            Senão
                registrar_alerta(produto.codigo, "ESTOQUE CRÍTICO")
            FimSe
            enviar_notificacao_compras(produto.codigo)
        FimSe
    FimPara
Fim

RN-03: Bloqueio contra Ruptura

O PDV local impede a venda de itens sem saldo físico ativo no caixa, evitando faturamento fictício e insatisfação.

RN-04: Sugestão de Compra Automática

Produtos em nível crítico geram automaticamente solicitações de compra ponderadas pelo seu giro de vendas semanal.
